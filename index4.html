01 — VISÃO GERAL

Visão Geral

O SuperSistema é uma aplicação desktop Java que centraliza a gestão de usuários de uma organização com múltiplas filiais. A interface gráfica (Swing) conecta-se diretamente a um banco MySQL remoto via JDBC. Cada ação sensível é registrada em um log de auditoria persistente.

FuncionalidadeImplementaçãoClasse(s)
AutenticaçãoSELECT com PreparedStatement; valida login + senha no bancoLoginDialog
Seleção de empresaJComboBox estático com 5 opções (Matriz + 4 filiais)LoginDialog
Menus dinâmicosMenus Usuários e Segurança só aparecem após loginFormPrincipal
Listar usuáriosSELECT ordenado por nome; JTable somente leituraFormUsuariosListar
Incluir usuárioINSERT com PreparedStatement; diálogo modalFormUsuariosIncluir + FormUsuarioEditar
Editar usuárioUPDATE por usuario_id; pré-carrega campos do bancoFormUsuarioEditar
Excluir usuárioDELETE com confirmação; aviso de irreversibilidadeFormUsuariosExcluir
Log de auditoriaAppend em arquivo texto; formato pipe-delimitedAuditoriaUtil + FormLogAuditoria
Arquitetura em duas camadas A interface Swing acessa o banco MySQL diretamente via JDBC — sem DAO, sem ORM, sem camada intermediária formal. A auditoria é uma preocupação transversal implementada via chamadas estáticas a AuditoriaUtil.registrar() em todos os pontos de persistência.

Conexao.java — código completo 
public class Conexao {
    private static final String URL    = "jdbc:mysql://bd_savir.mysql.dbaas.com.br:3306/bd_savir?useSSL=false&serverTimezone=America/Fortaleza";
    private static final String USUARIO = "bd_savir";
    private static final String SENHA   = "B@nc0D@d0s";

    static {
        // Bloco estático: carrega o driver UMA vez quando a classe é inicializada pela JVM
        try { Class.forName("com.mysql.cj.jdbc.Driver"); }
        catch (ClassNotFoundException e) { e.printStackTrace(); }
    }

    public static Connection getConnection() throws Exception {
        return DriverManager.getConnection(URL, USUARIO, SENHA);
    }

    public static boolean testarConexao() {
        try (Connection conn = getConnection()) {
            return conn != null;
        } catch (Exception e) {
            System.err.println("Erro ao conectar: " + e.getMessage());
            return false;
        }
    }
}
⚠ Credenciais hardcoded URL, usuário e senha do banco estão em texto claro no código-fonte. Qualquer pessoa com acesso ao .java ou mesmo ao .class descompilado vê as credenciais. Ver seção Segurança para a solução correta.
05 — INFRAESTRUTURA

AuditoriaUtil.java

Classe de utilidade estática. O método registrar() abre o arquivo em modo append, escreve uma linha e fecha imediatamente. Qualquer falha de I/O é impressa no System.err mas nunca propaga uma exceção — o sistema continua funcionando mesmo sem log.

AuditoriaUtil.java — método registrar() 
public static void registrar(String login, String evento, String detalhe) {
    String dataHora = LocalDateTime.now().format(FORMATO);
    // monta: "yyyy-MM-dd HH:mm:ss | login | EVENTO | detalhe"
    String linha = dataHora + " | " + login + " | " + evento + " | " + detalhe;

    try {
        FileWriter fw = new FileWriter(ARQUIVO_LOG, true); // true = append
        PrintWriter pw = new PrintWriter(fw);
        pw.println(linha);
        pw.close(); // fecha FileWriter também
    } catch (IOException e) {
        System.err.println("Erro ao gravar auditoria: " + e.getMessage());
        // falha silenciosa — não interrompe a aplicação
    }
}

06 — AUTENTICAÇÃO

LoginDialog.java

Diálogo modal que bloqueia o FormPrincipal enquanto o usuário não se autentica ou cancela. Valida todos os campos, testa a conexão com o banco e só então executa a query de autenticação.

LoginDialog.java — método validarLogin() — núcleo da autenticação 
private void validarLogin(String usuarioLogin, String senhaLogin, String empresaSelecionada) {

    // 1. Testa se o banco está disponível antes de qualquer coisa
    if (!Conexao.testarConexao()) {
        JOptionPane.showMessageDialog(this, "Não foi possível conectar ao banco.", "Erro de Conexão", JOptionPane.ERROR_MESSAGE);
        return;
    }

    String sql = "SELECT nome FROM tb_usuarios WHERE login = ? AND senha = ? LIMIT 1";

    try (Connection conn = Conexao.getConnection();
         PreparedStatement pst = conn.prepareStatement(sql)) {

        pst.setString(1, usuarioLogin);  // ? → login digitado
        pst.setString(2, senhaLogin);    // ? → senha digitada

        ResultSet rs = pst.executeQuery();

        if (rs.next()) {
            // Credenciais válidas: captura dados e fecha
            autenticado    = true;
            usuario        = rs.getString("nome");
            loginDigitado  = usuarioLogin;
            empresa        = empresaSelecionada;
            dispose();
        } else {
            // Credenciais inválidas: mensagem + limpa senha + foca usuário
            JOptionPane.showMessageDialog(this, "Usuário ou senha inválidos!", "Erro de Autenticação", JOptionPane.ERROR_MESSAGE);
            campoSenha.setText("");
            campoUsuario.requestFocus();
        }
    } catch (Exception e) { /* exibe erro + e.printStackTrace() */ }
}

private void aplicarEstadoAutenticacao() {
    boolean logado = (usuarioLogado != null);
    itemLogin.setText(logado ? "Logout" : "Logar");

    if (logado) {
        // Cria os menus uma única vez (lazy initialization)
        if (menuUsuarios == null) {
            menuUsuarios = new JMenu("Usuários");
            itemGestaoUsuarios = new JMenuItem("Gestão de Usuários");
            itemGestaoUsuarios.addActionListener(e ->
                new FormUsuariosListar(loginUsuarioLogado));
            menuUsuarios.add(itemGestaoUsuarios);
        }
        if (!isMenuPresente(menuUsuarios))  menuBar.add(menuUsuarios);
        if (!isMenuPresente(menuSeguranca)) menuBar.add(menuSeguranca);
    } else {
        // Remove os menus ao fazer logout
        if (isMenuPresente(menuUsuarios))  menuBar.remove(menuUsuarios);
        if (isMenuPresente(menuSeguranca)) menuBar.remove(menuSeguranca);
    }

    menuBar.revalidate(); // recalcula layout da barra
    menuBar.repaint();    // redesenha a barra na tela
}

// Busca todos os usuários e preenche a tabela
public void carregarUsuarios() {
    modelo.setRowCount(0); // limpa a tabela antes de recarregar
    String sql = "SELECT usuario_id, nome, login, email FROM tb_usuarios ORDER BY nome";
    try {
        Connection conn = Conexao.getConnection();
        PreparedStatement stmt = conn.prepareStatement(sql);
        ResultSet rs = stmt.executeQuery();
        while (rs.next()) {
            modelo.addRow(new Object[]{
                rs.getInt("usuario_id"), rs.getString("nome"),
                rs.getString("login"), (rs.getString("email") != null ? rs.getString("email") : "—")
            });
        }
        rs.close(); stmt.close(); conn.close();
    } catch (Exception e) { /* exibe JOptionPane de erro */ }
}

FormUsuarioEditar — INSERT e UPDATE no mesmo formulário

Modo de operação O mesmo JDialog serve para inclusão e edição. O parâmetro usuarioId determina o modo: 0 → INSERT (título "Incluir Usuário"), >0 → UPDATE (título "Editar Usuário" + pré-carrega campos do banco).
FormUsuarioEditar.java — lógica de salvar() 
private void salvar() {
    String nome  = campoNome.getText().trim();
    String login = campoLogin.getText().trim();
    String senha = new String(campoSenha.getPassword()).trim();
    String email = campoEmail.getText().trim();

    // Validações obrigatórias
    if (nome.isEmpty())  { /* avisa + foco */ return; }
    if (login.isEmpty()) { /* avisa + foco */ return; }
    if (senha.isEmpty()) { /* avisa + foco */ return; }

    try {
        Connection conn = Conexao.getConnection();
        PreparedStatement stmt;

        if (usuarioId == 0) {
            // MODO INCLUSÃO → INSERT
            stmt = conn.prepareStatement("INSERT INTO tb_usuarios (nome, login, senha, email) VALUES (?, ?, ?, ?)");
            stmt.setString(1, nome); stmt.setString(2, login);
            stmt.setString(3, senha); stmt.setString(4, email.isEmpty() ? null : email);
        } else {
            // MODO EDIÇÃO → UPDATE
            stmt = conn.prepareStatement("UPDATE tb_usuarios SET nome=?, login=?, senha=?, email=? WHERE usuario_id=?");
            stmt.setString(1, nome); stmt.setString(2, login);
            stmt.setString(3, senha); stmt.setString(4, email.isEmpty() ? null : email);
            stmt.setInt(5, usuarioId);
        }
        stmt.executeUpdate(); stmt.close(); conn.close();

        salvo = true;
        AuditoriaUtil.registrar(loginOperador, usuarioId == 0 ? "INCLUIR_USUARIO" : "EDITAR_USUARIO", "login=" + login);
        dispose();
    } catch (Exception e) {
        if (e.getMessage().contains("Duplicate entry")) {
            // Login já existe — mensagem específica
            JOptionPane.showMessageDialog(this, "Este login já está em uso.", "Login Duplicado", JOptionPane.ERROR_MESSAGE);
            campoLogin.requestFocus();
        } else { /* erro genérico */ }
    }
}

FormUsuariosExcluir — exclusão com confirmação

FormUsuariosExcluir.java — fluxo completo de exclusão 
public static void excluir(FormUsuariosListar formListar, String loginOperador) {
    int linha = formListar.tabela.getSelectedRow();
    if (linha == -1) { /* avisa para selecionar */ return; }

    int id    = (int) formListar.modelo.getValueAt(linha, 0);
    String nome = (String) formListar.modelo.getValueAt(linha, 1);

    // Confirmação obrigatória com aviso de irreversibilidade
    int ok = JOptionPane.showConfirmDialog(formListar,
        "Deseja excluir \"" + nome + "\"?\nEsta ação não pode ser desfeita.",
        "Confirmar Exclusão", JOptionPane.YES_NO_OPTION, JOptionPane.WARNING_MESSAGE);
    if (ok != JOptionPane.YES_OPTION) return;

    try {
        Connection conn = Conexao.getConnection();
        PreparedStatement stmt = conn.prepareStatement("DELETE FROM tb_usuarios WHERE usuario_id = ?");
        stmt.setInt(1, id); stmt.executeUpdate(); stmt.close(); conn.close();

        AuditoriaUtil.registrar(loginOperador, "EXCLUIR_USUARIO", "id=" + id + ", nome=" + nome);
        formListar.carregarUsuarios(); // recarrega a grade
    } catch (Exception e) { /* erro no DELETE */ }
}
09 — LOG DE AUDITORIA (VISUALIZADOR)

FormLogAuditoria.java

Janela que exibe o conteúdo do auditoria.log em uma tabela interativa. Lê o arquivo linha a linha, divide pelo separador | e exibe em 4 colunas. Rola automaticamente para o registro mais recente.

FormLogAuditoria.java — método carregarLog() 
private void carregarLog() {
    modelo.setRowCount(0); // limpa antes de recarregar

    try {
        BufferedReader br = new BufferedReader(new FileReader(ARQUIVO_LOG));
        String linha;
        while ((linha = br.readLine()) != null) {
            String[] partes = linha.split("\\|"); // divide pelo |
            if (partes.length == 4) {             // só processa linhas com 4 campos
                modelo.addRow(new Object[]{
                    partes[0].trim(), partes[1].trim(),
                    partes[2].trim(), partes[3].trim()
                });
            }
        }
        br.close();

        // Rola para a última linha (registro mais recente fica no final)
        if (modelo.getRowCount() > 0) {
            tabela.scrollRectToVisible(tabela.getCellRect(modelo.getRowCount() - 1, 0, true));
        }
    } catch (FileNotFoundException e) {
        // Situação normal antes do primeiro login — mensagem amigável
        JOptionPane.showMessageDialog(this,
            "Nenhum registro encontrado ainda.\nO arquivo será criado no primeiro login.",
            "Log Vazio", JOptionPane.INFORMATION_MESSAGE);
    } catch (IOException e) { /* erro de leitura */ }
}

compile.sh — script de compilação 
#!/bin/bash
MYSQL_JAR="/usr/share/java/mysql-connector-j-9.7.0.jar"

# Verifica driver
if [ ! -f "$MYSQL_JAR" ]; then
    echo "Driver MySQL não encontrado em $MYSQL_JAR"; exit 1

# Entra em src/, limpa .class antigos e compila todos os .java
cd src
find . -name "*.class" -type f -delete
javac -cp ".:$MYSQL_JAR" javasistema/*.java
run.sh — script de execução 
#!/bin/bash
MYSQL_JAR="/usr/share/java/mysql-connector-j-9.7.0.jar"

fi

# Executa a partir de src/ (importante: auditoria.log fica aqui)
cd src
java -cp ".:$MYSQL_JAR" javasistema.FormPrincipal

14 — SEGURANÇA

Pontos de Atenção — Segurança

Limitações conhecidas do projeto atual, relevantes para evolução para produção. Nenhuma é bloqueante para uso em ambiente controlado/acadêmico, mas todas devem ser endereçadas antes de qualquer implantação real.

01
Credenciais do banco hardcoded

URL, usuário e senha do banco de dados estão literais em Conexao.java. Qualquer pessoa com acesso ao repositório ou ao .class descompilado vê as credenciais.

Solução: Mover para arquivo config.properties fora do repositório, lido via Properties.load(), e adicionar ao .gitignore.

CRÍTICO
02
Senhas de usuários em texto plano

A coluna senha em tb_usuarios armazena senhas sem nenhum hash. Vazamento do banco expõe todas as senhas diretamente.

Solução: Aplicar BCrypt ou MessageDigest (SHA-256 + salt único por usuário) antes de persistir e na comparação durante autenticação.

CRÍTICO
03
Sem limite de tentativas de login

Não há proteção contra tentativas repetidas de autenticação. O sistema aceita quantas tentativas o usuário quiser.

Solução: Adicionar contador de tentativas por sessão. Após N falhas, bloquear por tempo fixo (ex: 30s) ou exigir confirmação adicional.

ALTO
04
Sem controle de perfis/permissões

Qualquer usuário autenticado tem acesso a todas as funcionalidades — não há diferença entre admin e operador comum.

Solução: Adicionar coluna perfil ENUM('admin','operador') em tb_usuarios e exibir apenas os menus compatíveis com o perfil logado.

MÉDIO
05
Log de auditoria editável manualmente

O arquivo auditoria.log é texto simples sem proteção criptográfica. Pode ser editado ou apagado sem deixar rastro.

Solução: Mover log para tabela tb_auditoria no banco com restrições de DELETE, ou assinar as linhas com HMAC para detecção de adulteração.

MÉDIO
06
Conexões não fechadas com try-with-resources

Vários métodos abrem Connection e fecham manualmente com .close(). Se uma exceção ocorrer entre a abertura e o fechamento, a conexão vaza.

Solução: Usar try (Connection c = ...; PreparedStatement s = ...) { ... } — o try-with-resources garante fechamento mesmo em caso de exceção.

15 — MELHORIAS SUGERIDAS

Melhorias Sugeridas

Evoluções técnicas que elevariam o projeto a um padrão de produção. Organizadas por impacto.

MelhoriaImpactoComo implementar
Hash de senha (BCrypt) Segurança Adicionar org.mindrot:jbcrypt. BCrypt.hashpw(senha, BCrypt.gensalt()) ao salvar; BCrypt.checkpw() ao autenticar.
Config externo Segurança Properties p = new Properties(); p.load(new FileReader("config.properties")). Arquivo fora do repo.
Padrão DAO Arquitetura Criar UsuarioDAO com findAll(), findById(), insert(), update(), delete(). As classes GUI chamam o DAO — sem SQL espalhado.
try-with-resources consistente Qualidade Substituir todos os conn.close() manuais por try (Connection c = ...) { ... } em todos os métodos de acesso ao banco.
Log em tabela no banco Confiabilidade Criar tb_auditoria (id, dt_hora, login, evento, detalhe). AuditoriaUtil passa a fazer INSERT em vez de escrever em arquivo.
Controle de perfis Funcionalidade Adicionar perfil ENUM('admin','operador'). FormPrincipal exibe menus conforme o perfil retornado no login.
Busca/filtro na listagem UX JTextField de busca + RowFilter no TableRowSorter — filtra sem nova query ao banco.
Paginação Performance LIMIT ? OFFSET ? no SELECT de listagem + controles de página na toolbar.
Prioridade mínima para produção Os dois primeiros itens da tabela (hash de senha + config externo) são os únicos que precisam ser resolvidos antes de qualquer uso fora de ambiente de desenvolvimento. Todos os outros são melhorias de qualidade/arquitetura que podem ser implementadas iterativamente.
