Antes de começar

Como um programa Java funciona?

Imagine que um programa Java é como uma receita de bolo muito organizada. Ela tem ingredientes (variáveis), etapas (comandos), e um cozinheiro central que segue tudo na ordem certa. Veja os blocos que formam nosso programa:

📦
Classe (class)
É a "caixa" que contém o programa inteiro. Todo código Java vive dentro de uma classe.
🚪
Método main
É a porta de entrada. O computador sempre começa a ler um programa Java por aqui, obrigatoriamente.
🔧
Métodos (funções)
São "blocos de tarefas com nome" que você chama quando precisa. Como chamar um assistente específico para cada serviço.
🗃️
Variáveis
São caixinhas na memória do computador que guardam informações — números, textos, ou verdadeiro/falso.
🔁
while (enquanto)
Repete um bloco de código enquanto uma condição for verdadeira. É o "loop" do programa.
🔀
if / switch
São "decisores". O programa olha para um valor e decide qual caminho seguir, como um GPS escolhendo a rota.
Os 3 pilares obrigatórios

if, switch e while — explicados sem mistério

🔁 O while — "Enquanto isso..." while

O while é como um porteiro que fica perguntando: "Você quer sair?" Enquanto a resposta for não, ele continua deixando você entrar no programa de novo. Assim que você disser 0 (sair), ele encerra.

No nosso código: while (opcao != 0) significa literalmente: "enquanto a opção escolhida for diferente de zero, continue rodando".

🔀 O switch — "Seletor de canais" switch

O switch funciona exatamente como um controle remoto de TV. Você digita um número, e o programa vai direto para o "canal" correspondente — sem ficar testando uma condição por vez.

case 1: → vai para Senhas | case 2: → vai para Golpes | default: → se nenhum case bater, cai aqui.

🤔 O if — "Perguntador" if / else if / else

O if é uma pergunta de sim ou não. Se a condição for verdadeira, faz uma coisa; senão (else), faz outra. O else if é como um plano B antes do plano C.

No módulo de senhas: se o tamanho ≥ 12 → ótimo | se ≥ 8 → razoável | senão → fraca. É uma escada de condições.

Explicação detalhada

Linha 1 — Importando a ferramenta de leitura

L1
import java.util.Scanner;
Importando o Scanner
import significa "trazer de fora". O Java tem uma biblioteca gigante de ferramentas prontas, e aqui estamos buscando especificamente a ferramenta chamada Scanner.

O Scanner é responsável por ler o que o usuário digita no teclado. Sem importar ele, o programa não conseguiria receber dados do usuário.

O ponto e vírgula ; no final é obrigatório em Java — é como o ponto final de uma frase. Toda instrução termina com ;.
É como pegar uma calculadora da gaveta antes de começar a fazer contas — você precisa ter a ferramenta em mãos antes de usá-la.

Linha 3 — Criando a classe principal

L3
public class GuiaSegurancaDigital {
A "caixa" que contém tudo
Em Java, todo o código precisa estar dentro de uma classe. Pense nela como uma pasta de arquivo com um nome.

• public → qualquer parte do programa pode usar esta classe
• class → palavra mágica que cria a classe
• GuiaSegurancaDigital → o nome escolhido (sem espaços, começa com maiúscula)
• { → abre a caixa. Tudo que ficar entre { e } pertence a esta classe.
É como criar uma empresa chamada "GuiaSegurancaDigital" — tudo que acontece neste programa acontece dentro desta empresa.

Linha 5 — Criando o "ouvinte" do teclado

L5
static Scanner sc = new Scanner(System.in);
Criando o leitor de teclado chamado "sc"
Esta linha cria uma variável chamada sc (abreviação de Scanner) que vai ficar de prontidão o tempo todo para capturar o que o usuário digitar.

• static → significa que todos os métodos da classe podem usar este sc sem precisar recriá-lo
• Scanner sc → cria a variável do tipo Scanner com o apelido "sc"
• new Scanner(System.in) → instancia (fabrica) um novo Scanner ligado ao teclado (System.in = entrada do sistema = teclado)
É como contratar um assistente chamado "sc" cuja única função é ficar escutando o que você digita e trazer essa informação para o programa.
Como esta variável fica "fora" dos métodos mas dentro da classe, ela pode ser usada por qualquer método — isso se chama variável de instância.

Linha 7 — A porta de entrada obrigatória

L7
public static void main(String[] args) {
O método main — início absoluto de tudo
Esta é a linha mais especial de qualquer programa Java. Quando você clica em "executar", o computador procura exatamente esta linha e começa daqui.

• public → visível de fora (para a máquina virtual Java poder chamar)
• static → existe mesmo antes de criar qualquer objeto
• void → este método não retorna nenhum valor ao finalizar
• main → este nome exato é obrigatório — é o ponto de partida universal
• String[] args → parâmetros que podem ser passados ao iniciar (não usamos neste programa, mas é obrigatório declarar)
É o "Capítulo 1, página 1" do livro. O Java sempre abre aqui — sem main, o programa simplesmente não roda.

Linha 8 — A variável que guarda a escolha do usuário

L8
int opcao = -1;
Criando a caixinha "opcao" com valor inicial -1
• int → tipo de dado: número inteiro (sem casas decimais). Ex: 0, 1, 2, -1
• opcao → nome da variável (caixinha na memória)
• = -1 → valor inicial. Por que -1? Porque -1 nunca é uma opção válida do menu, então o programa entra no loop while imediatamente

Se colocássemos 0 como valor inicial, o while nunca rodaria (pois 0 significa sair).
É como colocar um post-it em branco na mesa antes da reunião começar — você sabe que vai preencher logo, mas precisa que ele exista primeiro.

Linhas 11–36 — O loop while (o coração do programa)

💡 O que é um loop? Um loop é um bloco de código que se repete automaticamente. O while repete enquanto uma condição for verdadeira — assim que a condição falha, ele para.
L11
while (opcao != 0) {
O loop principal — "enquanto não sair, continue"
!= significa "diferente de". Então: "enquanto opcao for diferente de 0, execute o bloco { }".

Quando o usuário digitar 0, opcao recebe o valor 0, a condição opcao != 0 se torna FALSA, e o loop encerra.
É como um Netflix que continua sugerindo filmes enquanto você não clicar em "Sair". Cada volta = um novo menu aparecendo.

Linhas 12–18 — Imprimindo o menu na tela

L12
System.out.println("\n===============================");
System.out.println — imprimir e pular linha
System.out.println é o comando para escrever texto na tela e depois pular uma linha automaticamente. Pense nele como o Enter automático.

O \n dentro da string é um caractere especial chamado escape de nova linha — ele pula uma linha antes de imprimir o texto. Isso cria um espaço visual entre menus.
"System.out.println" = "escreve isso na tela e aperta Enter".
L18
System.out.print("Escolha uma opção: ");
System.out.print (sem o "ln") — imprimir SEM pular linha
print (sem o ln no final) imprime o texto mas não pula linha. O cursor fica na mesma linha, esperando o usuário digitar na continuação.

Resultado visual: Escolha uma opção: _ (o cursor fica logo depois dos dois pontos)
L20
opcao = lerInteiro();
Capturando a escolha do usuário
Chama o método lerInteiro() (que veremos na linha 82) e guarda o resultado na variável opcao.

O = aqui é de atribuição: "coloque o resultado de lerInteiro() dentro de opcao". É diferente do == de comparação.
É como pedir que o assistente "sc" vá ao balcão de atendimento, pegue o número que o cliente digitou e traga de volta para o gerente (main).

Linhas 23–35 — O switch: o direcionador de rotas

Por que usar switch em vez de vários if? Quando você precisa comparar uma variável contra muitos valores fixos, o switch é mais limpo e legível que encadear vários if-else. O Java também consegue otimizá-lo melhor.
L23
switch (opcao) {
Abrindo o switch com a variável opcao
O switch recebe uma variável (aqui, opcao) e vai procurar qual case combina com o valor dela.
Imagine uma portaria com várias portas numeradas. O switch olha o número na sua ficha e te manda para a porta certa.
L24–26
case 1: moduloSenhas(); break;
case 1 — executar o módulo de Senhas
• case 1: → se opcao for igual a 1, execute o que vem abaixo
• moduloSenhas() → chama o método moduloSenhas (o programa "pula" para lá e executa)
• break → "pare aqui e saia do switch". Sem o break, o Java continuaria executando o próximo case automaticamente (efeito indesejado chamado fall-through)
O break é obrigatório na maioria dos cases! Esquecer o break é um erro comum que faz o programa executar vários cases ao mesmo tempo.
L27–29
case 2: moduloGolpes(); break;
case 2 — executar o módulo de Golpes
Mesma lógica do case 1, mas chama moduloGolpes(). Cada case é um caminho diferente para o mesmo seletor.
L30–32
case 0: System.out.println("\nAté mais!"); break;
case 0 — despedida e saída do loop
Quando opcao for 0: imprime a mensagem de tchau e faz o break.

Depois do break, o switch termina, e o while testa a condição opcao != 0 de novo. Como agora opcao = 0, a condição é FALSA e o loop encerra. O programa termina.
L33–34
default: System.out.println("Opção inválida.");
default — o "senão" do switch
Se o usuário digitar qualquer número que não seja 0, 1 ou 2, o switch cai no default. É o caso curinga — "nenhum dos cases acima bateu, então execute isto".

Note que o default não precisa de break (é o último bloco). O programa vai mostrar a mensagem de erro e voltar ao início do while.
É como uma recepcionista que, quando você pede algo fora do cardápio, diz: "Essa opção não existe, por favor escolha outra."

Linhas 39–59 — Módulo de Senhas Seguras

L39
static void moduloSenhas() {
Definindo o método moduloSenhas
• static → pertence à classe, não a um objeto específico
• void → este método não retorna nenhum valor ao terminar
• moduloSenhas() → nome do método + parênteses vazios (não recebe parâmetros)

Este método só é executado quando chamado — na linha 25, quando o switch chama moduloSenhas();
É como ter um funcionário especialista em senhas. Você só o chama quando precisa dele; ele não fica trabalhando o tempo todo.
L40–47
System.out.println("\n--- SENHAS SEGURAS ---"); System.out.println("Uma boa senha deve ter:"); System.out.println("- Pelo menos 12 caracteres"); // ... mais linhas de conteúdo ... System.out.print("Quantos caracteres tem sua senha? ");
Exibindo o conteúdo educativo sobre senhas
Uma série de println que imprime as dicas de segurança. Cada linha é uma instrução separada — o Java executa uma por vez, de cima para baixo.

A linha 47 usa print (sem ln) para que o cursor fique na mesma linha, esperando o usuário digitar o número de caracteres da senha.
L49
int tamanho = lerInteiro();
Lendo quantos caracteres a senha tem
Cria uma nova variável inteira chamada tamanho e armazena o número digitado pelo usuário (obtido via lerInteiro()).

Linhas 52–58 — O if/else if/else: avaliando a senha

Diferença entre = e == Em Java: = é atribuição (guardar um valor). >= é comparação (maior ou igual que). Confundi-los é um dos erros mais comuns!
L52
if (tamanho >= 12) {
if — primeira verificação (senha forte)
Se o tamanho digitado for maior ou igual a 12, executa o bloco { }.
>= = "maior ou igual que"

Se essa condição for verdadeira, as linhas 52 e 53 são executadas, e o programa pula direto para o final do bloco if-else (linha 58).
L54
} else if (tamanho >= 8) {
else if — plano B (senha razoável)
Só chega aqui se a condição do if anterior for FALSA (ou seja, tamanho < 12).

Verifica se tamanho é maior ou igual a 8. Se sim → mensagem de aviso "razoável".

Neste ponto, sabemos implicitamente que tamanho está entre 8 e 11 (pois o if anterior já descartou ≥ 12).
L56–57
} else { System.out.println("✗ Senha curta!"); }
else — plano C (senha fraca)
O else sem condição é o "em todos os outros casos". Chegando aqui, sabemos que tamanho < 8 — a senha é muito curta e vulnerável.

O } fecha o bloco if-else-if-else.
É como uma escada de avaliação: Primeiro testa o melhor caso (≥12), depois o intermediário (≥8), e o que sobrar cai no pior caso.

Segundo método de conteúdo — sobre golpes
Mesma estrutura do moduloSenhas(): um método void que imprime conteúdo educativo e depois faz uma pergunta ao usuário. Demonstra a reutilização do padrão — uma boa prática de programação.

Conteúdo educativo + pergunta binária
Imprime os 3 tipos de golpes comuns e então pergunta ao usuário se ele já recebeu algum. A resposta será 1 (Sim) ou 2 (Não) — um padrão simples de sim/não com números.
L70

Guardando a resposta do usuário
Nova variável local resposta recebe o número digitado. Note que esta variável só existe dentro de moduloGolpes() — ela é uma variável local.
L72–79

if/else simples — dois caminhos possíveis
Um if/else binário: se resposta for exatamente igual a 1 (Sim), mostra dicas de recuperação. Caso contrário (else), mostra dicas preventivas.

== com dois sinais de igual é comparação. Um único = seria atribuição (erro!).

Linhas 82–88 — O método lerInteiro: proteção contra erros

Por que precisamos deste método? Se o usuário digitar uma letra quando o programa espera um número, o Scanner lança uma exceção (erro) e o programa trava. O lerInteiro() resolve isso com elegância.
L82
static int lerInteiro() {
Método que retorna um int — diferente do void!
Desta vez, o método não é void. É int — significa que ele retorna (devolve) um número inteiro para quem o chamou.

Quando chamamos opcao = lerInteiro(), este método executa e entrega um número que vai para a variável opcao.
L83–86
while (!sc.hasNextInt()) { System.out.print("Digite um número válido: "); sc.next(); }
while interno — rejeitando entradas inválidas
• sc.hasNextInt() → pergunta ao Scanner: "o próximo token digitado é um número inteiro?"
• ! (negação) → inverte: "enquanto NÃO for um número inteiro..."
• sc.next() → descarta a entrada inválida (lê e joga fora, para não ficar em loop infinito)

Este loop fica repetindo até o usuário digitar um número de verdade.
É como uma catraca que só gira se você apresentar o bilhete certo. Se apresentar algo errado, ela pede de novo e descarta a tentativa inválida.
L87
return sc.nextInt();
return — devolvendo o número válido
Chegou aqui, sabemos que o próximo valor é um inteiro válido.
• sc.nextInt() → lê o número inteiro digitado
• return → devolve esse número para quem chamou o método

O valor retornado é o que fica na variável do lado de fora (ex: opcao = lerInteiro()).
L88–89
} // fecha lerInteiro } // fecha a classe GuiaSegurancaDigital
Fechando os blocos abertos
Cada { aberta em algum ponto do código precisa de seu } correspondente para fechar. A contagem de chaves precisa bater perfeitamente — se faltar uma, o programa nem compila.
São como parênteses em matemática: cada um que abre precisa de um par que fecha.
Conteúdo educativo

🔑 Senhas Seguras — O que o programa ensina

O módulo de senhas do programa aborda estes pontos — aqui explicamos cada um em profundidade:

📏

Mínimo de 12 caracteres

Quanto mais longa a senha, mais combinações um hacker precisa testar. Uma senha de 8 dígitos tem 100 bilhões de combinações; uma de 12 tem 3 quintilhões. O comprimento é a proteção mais eficaz.

🔡

Mistura de tipos de caracteres

Usar maiúsculas, minúsculas, números e símbolos expande o "alfabeto" de cada posição. Isso multiplica exponencialmente o número de tentativas para forçar a senha.

🚫

Sem dados pessoais

Datas de aniversário, nomes de pets, placa do carro — golpistas pesquisam nas redes sociais antes de tentar uma invasão. Evite qualquer informação que alguém possa adivinhar sobre você.

🔒

Uma senha por serviço

Se você usa a mesma senha no e-mail e no banco, e um site é invadido, o criminoso tem acesso a tudo. Use um gerenciador de senhas (como Bitwarden ou 1Password) para manter senhas únicas.

💡 Dica prática: A técnica da frase-senha Escolha 4 palavras aleatórias e junte-as: BananaAzulTelhadoXícara. É longa, fácil de lembrar e extremamente difícil de quebrar. Adicione um número e símbolo para ficar perfeita.

🎣 Golpes Online — O que o programa ensina

🎣

Phishing — E-mail ou link falso

O criminoso envia um e-mail ou mensagem se passando por um banco, empresa ou órgão do governo. O link leva a um site idêntico ao original, mas falso — e tudo que você digitar vai para o golpista.


Como identificar: endereço do remetente estranho, urgência excessiva ("sua conta será bloqueada em 2 horas!"), link com erros ortográficos (ex: bradesc0.com ao invés de bradesco.com).

📞

Falso Suporte Técnico

O golpista liga se passando por funcionário do banco, da operadora ou da Microsoft. Diz que detectou um problema e pede acesso remoto ao seu computador ou que você instale um aplicativo.


Como se proteger: Empresas legítimas nunca ligam pedindo sua senha ou acesso remoto. Desligue e ligue você mesmo para o número oficial da empresa.

💸

Golpe do Pix / Pagamento Urgente

A vítima recebe uma mensagem de familiar ou amigo (conta hackeada) pedindo um Pix urgente. Ou recebe uma "promoção" que exige pagamento imediato via Pix antes de receber o prêmio.


Como se proteger: Sempre confirme via ligação de voz para o número salvo na sua agenda. Nunca faça Pix por pressão ou urgência.

A O programa trava com erro
B Cai no default do switch e mostra "Opção inválida"
C O programa encerra
D Vai para o módulo de senhas
✅ Correto! O switch tem um bloco default para exatamente esse caso — qualquer número que não seja 0, 1 ou 2.
❌ Não exatamente. O switch tem um bloco default que captura qualquer valor não previsto e exibe uma mensagem de erro amigável.
2. Por que a variável opcao começa com o valor -1?
A Para causar um erro intencional
B Por convenção — todo programa Java começa com -1
C Para garantir que o loop while execute pelo menos uma vez (-1 ≠ 0)
D Porque -1 representa "erro" em Java
✅ Exato! Se começasse com 0, a condição opcao != 0 seria imediatamente falsa e o programa encerraria antes de mostrar qualquer coisa.
❌ Tente de novo. Pense: se opcao começasse com 0, o que aconteceria com a condição do while?
3. Qual é a diferença entre println e print?
A Não há diferença — são a mesma coisa
B println pula linha após imprimir; print fica na mesma linha
C print é mais rápido que println
D print só funciona com números
✅ Perfeito! O "ln" em println significa "line" — ele adiciona uma quebra de linha automaticamente após o texto.
❌ A diferença está no "ln" do println, que significa "line" — ele pula uma linha depois de imprimir. O print não pula.
