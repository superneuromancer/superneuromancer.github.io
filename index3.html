Before we start

How does a Java program work?

Imagine a Java program is like a very well-organized cake recipe. It has ingredients (variables), steps (commands), and a central chef who follows everything in the right order. Here are the blocks that make up our program:

📦
Class (class)
It's the "box" that holds the entire program. All Java code lives inside a class.
🚪
Main Method
It's the entry door. The computer always starts reading a Java program here, no exceptions.
🔧
Methods (functions)
They are "named task blocks" you call when needed. Like calling a specific assistant for each job.
🗃️
Variables
They are little boxes in computer memory that store information — numbers, text, or true/false.
🔁
while (loop)
Repeats a block of code while a condition is true. It's the program's "loop".
🔀
if / switch
They are "decision makers". The program looks at a value and decides which path to take, like a GPS choosing a route.
The 3 required pillars

if, switch and while — explained simply

🔁 The while — "Meanwhile..." while

The while is like a doorman who keeps asking: "Do you want to leave?" While the answer is no, it keeps letting you back into the program. Once you say 0 (exit), it shuts down.

In our code: while (opcao != 0) literally means: "while the chosen option is different from zero, keep running".

🔀 The switch — "Channel selector" switch

The switch works exactly like a TV remote control. You type a number, and the program goes straight to the matching "channel" — without testing one condition at a time.

case 1: → goes to Passwords | case 2: → goes to Scams | default: → if no case matches, falls here.

🤔 The if — "The asker" if / else if / else

The if is a yes-or-no question. If the condition is true, do one thing; otherwise (else), do another. The else if is like plan B before plan C.

In the passwords module: if length ≥ 12 → great | if ≥ 8 → fair | otherwise → weak. It's a ladder of conditions.

Detailed explanation

Line 1 — Importing the reading tool

L1
import java.util.Scanner;
Importing the Scanner
import means "bring from outside". Java has a huge library of ready-made tools, and here we are specifically fetching the tool called Scanner.

The Scanner is responsible for reading what the user types on the keyboard. Without importing it, the program couldn't receive user input.

The semicolon ; at the end is mandatory in Java — it's like the period at the end of a sentence. Every statement ends with ;.
It's like taking a calculator out of the drawer before doing math — you need the tool at hand before using it.

Line 3 — Creating the main class

L3
public class GuiaSegurancaDigital {
The "box" that holds everything
In Java, all code must be inside a class. Think of it as a file folder with a name.

• public → any part of the program can use this class
• class → magic keyword that creates the class
• GuiaSegurancaDigital → the chosen name (no spaces, starts with uppercase)
• { → opens the box. Everything between { and } belongs to this class.
It's like creating a company called "GuiaSegurancaDigital" — everything that happens in this program happens inside this company.

Line 5 — Creating the keyboard "listener"

L5
static Scanner sc = new Scanner(System.in);
Creating the keyboard reader called "sc"
This line creates a variable called sc (short for Scanner) that will remain on standby at all times to capture what the user types.

• static → means all methods in the class can use this sc without recreating it
• Scanner sc → creates a Scanner-type variable nicknamed "sc"
• new Scanner(System.in) → instantiates (creates) a new Scanner connected to the keyboard (System.in = system input = keyboard)
It's like hiring an assistant called "sc" whose only job is to listen to what you type and bring that information to the program.
Since this variable is "outside" the methods but inside the class, it can be used by any method — this is called an instance variable.

Line 7 — The mandatory entry point

L7
public static void main(String[] args) {
The main method — the absolute beginning of everything
This is the most special line in any Java program. When you click "run", the computer looks for exactly this line and starts here.

• public → visible from outside (so the Java virtual machine can call it)
• static → exists even before any object is created
• void → this method returns no value when it finishes
• main → this exact name is required — it's the universal starting point
• String[] args → parameters that can be passed on startup (not used in this program, but mandatory to declare)
It's "Chapter 1, page 1" of the book. Java always opens here — without main, the program simply won't run.

Creating the "opcao" box with initial value -1

If we used 0 as the initial value, the while would never run (because 0 means exit).
It's like putting a blank sticky note on the desk before the meeting starts — you know you'll fill it in soon, but it needs to exist first.

Lines 11–36 — The while loop (the heart of the program)

💡 What is a loop? A loop is a block of code that repeats automatically. The while repeats while a condition is true — as soon as the condition fails, it stops.

!= means "different from". So: "while opcao is different from 0, execute the block { }".

When the user types 0, opcao receives the value 0, the condition opcao != 0 becomes FALSE, and the loop ends.
It's like Netflix that keeps suggesting movies until you click "Exit". Each loop = a new menu appearing.

Lines 23–35 — The switch: the route director

Why use switch instead of multiple ifs? When you need to compare a variable against many fixed values, the switch is cleaner and more readable than chaining multiple if-else. Java can also optimize it better.
L23
switch (opcao) {
Opening the switch with the opcao variable
The switch receives a variable (here, opcao) and looks for which case matches its value.
Imagine a reception area with several numbered doors. The switch looks at the number on your form and sends you to the right door.
L24–26
case 1: moduloSenhas(); break;
case 1 — run the Passwords module
• case 1: → if opcao equals 1, execute what follows
• moduloSenhas() → calls the moduloSenhas method (the program "jumps" there and executes)
• break → "stop here and exit the switch". Without break, Java would continue executing the next case automatically (unwanted effect called fall-through)
The break is mandatory in most cases! Forgetting the break is a common mistake that causes the program to execute multiple cases at the same time.
L27–29
case 2: moduloGolpes(); break;
case 2 — run the Scams module
Same logic as case 1, but calls moduloGolpes(). Each case is a different path for the same selector.
L30–32
case 0: System.out.println("\nAté mais!"); break;
case 0 — goodbye and exit the loop
When opcao is 0: prints the goodbye message and does the break.

After the break, the switch ends, and the while tests the condition opcao != 0 again. Since opcao is now 0, the condition is FALSE and the loop ends. The program terminates.
L33–34

default — the switch's "otherwise"
If the user types any number other than 0, 1, or 2, the switch falls to default. It's the wildcard case — "none of the above cases matched, so execute this".

Note that default doesn't need a break (it's the last block). The program will show the error message and return to the beginning of the while.
It's like a receptionist who, when you ask for something off the menu, says: "That option doesn't exist, please choose another."

Lines 52–58 — The if/else if/else: evaluating the password

Difference between = and == In Java: = is assignment (store a value). >= is comparison (greater than or equal to). Mixing them up is one of the most common mistakes!
L52
if (tamanho >= 12) {
if — first check (strong password)
If the typed length is greater than or equal to 12, execute the block { }.
>= = "greater than or equal to"

If this condition is true, lines 52 and 53 execute, and the program jumps directly to the end of the if-else block (line 58).
L54
} else if (tamanho >= 8) {
else if — plan B (fair password)
Only reaches here if the previous if condition is FALSE (i.e., length < 12).

Checks if length is greater than or equal to 8. If yes → "fair" warning message.

At this point, we implicitly know the length is between 8 and 11 (since the previous if already ruled out ≥ 12).
L56–57
} else { System.out.println("✗ Senha curta!"); }
else — plan C (weak password)
The else without a condition is "in all other cases". Reaching here, we know length < 8 — the password is too short and vulnerable.

The } closes the if-else-if-else block.
It's like an evaluation ladder: First tests the best case (≥12), then the middle (≥8), and whatever remains falls into the worst case.

🔑 Secure Passwords — What the program teaches

The program's passwords module covers these points — here we explain each one in depth:

📏

Minimum of 12 characters

The longer the password, the more combinations a hacker needs to test. An 8-digit password has 100 billion combinations; a 12-digit one has 3 quintillion. Length is the most effective protection.

🔡

Mix of character types

Using uppercase, lowercase, numbers and symbols expands the "alphabet" of each position. This exponentially multiplies the number of attempts needed to brute-force the password.

🚫

No personal data

Birthdays, pet names, license plates — scammers research social media before attempting an attack. Avoid any information someone could guess about you.

🔒

One password per service

If you use the same password for email and banking, and one site is breached, the criminal has access to everything. Use a password manager (like Bitwarden or 1Password) to maintain unique passwords.

💡 Practical tip: The passphrase technique Choose 4 random words and combine them: BlueBananaRooftopTeacup. It's long, easy to remember and extremely hard to crack. Add a number and symbol to make it perfect.

🎣 Online Scams — What the program teaches

🎣

Phishing — Fake email or link

The criminal sends an email or message posing as a bank, company, or government agency. The link leads to a site identical to the original, but fake — and everything you type goes to the scammer.


How to identify: strange sender address, excessive urgency ("your account will be blocked in 2 hours!"), link with spelling errors (e.g.: bradesc0.com instead of bradesco.com).

📞

Fake Technical Support

The scammer calls posing as a bank, carrier, or Microsoft employee. They say they detected a problem and ask for remote access to your computer or for you to install an application.


How to protect yourself: Legitimate companies never call asking for your password or remote access. Hang up and call the official company number yourself.

💸

Pix Scam / Urgent Payment

The victim receives a message from a family member or friend (hacked account) asking for an urgent Pix transfer. Or receives a "promotion" that requires immediate payment via Pix before receiving the prize.


How to protect yourself: Always confirm via voice call to the number saved in your contacts. Never make a Pix transfer under pressure or urgency.
